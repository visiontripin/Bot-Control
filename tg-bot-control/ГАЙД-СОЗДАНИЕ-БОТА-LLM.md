# Полный гайд для создания бота в BotControl через любую LLM

Этот документ — исчерпывающее руководство и готовый **Мастер-промт (Meta-Prompt)** для проектирования и генерации Telegram-ботов под **BotControl** с помощью любой LLM (ChatGPT, Claude, Gemini, Grok, Qwen, DeepSeek и локальных моделей).

В отличие от короткого промта в экране приложения («Скрипты → 🧠 Промт для создания бота»), этот гайд:
1. Заставляет LLM **сначала задать все уточняющие вопросы** — от степени иммерсивности и необходимости локального ИИ до расписания, анимаций, JS-скриптов с памятью `db`, вложенных inline-меню, медиа/опросов, пошаговых анкет FSM, ролей, рассылок, канала и режима объявлений.
2. Даёт LLM **полную техническую спецификацию всех возможностей** BotControl (Android APK и настольного `desktop-web` / `BotControl.exe`), включая точный синтаксис, ограничения и подводные камни импортёра.
3. Помогает получить с первого раза **готовый к импорту конфиг** без нераспознанных конструкций и с чётким планом проверки в приложении.

---

## Как пользоваться гайдом за 4 шага

1. Откройте чат с любой LLM.
2. Скопируйте весь блок из раздела **[1. Универсальный Мастер-промт для LLM](#1-универсальный-мастер-промт-для-llm)** (или прикрепите этот файл целиком к диалогу и попросите LLM действовать по инструкции внутри).
3. Ответьте на вопросы LLM (можно коротко, пунктами или написать «пункты 4 и 8 — на твой вкус»).
4. Полученный код вставьте в приложение:
   - **Android:** (если бот уже был настроен раньше и вы ставите нового бота с нуля, сначала сделайте **«♻ Сброс настроек бота»**) → тапните по боту → **Скрипты → Импорт настроек из кода** → вставьте код (или выберите `.py`/`.txt`) → **🔍 Разобрать** → проверьте число найденных правил, кнопки и раздел **«Замечания»** → **✅ Применить к боту** → **▶ Этот бот** → отправьте `/start` в Telegram.
   - **Windows / Linux / Termux (`desktop-web`):** вставьте сгенерированный JSON в импорт веб-интерфейса, нажмите **Проверить**, укажите токен и нажмите **Запустить**.

1. ПЛАТФОРМА И ЦЕЛЬ БОТА
   • Куда делаем бота:
     - Android-приложение BotControl `v1.9.0` (полный функционал: Python-конфиг, вложенные inline-меню до 3 уровней, клиентские кнопки `url`/`web_app`/`copy_text`/`switch_inline`, фото-анимации и слайдеры, медиа/стикеры/опросы, JS-скрипты с персистентной памятью `db`, локальный ИИ на телефоне, пошаговые анкеты FSM, CRM подписчиков и роли, проверка подписки на канал, массовые рассылки, автопостинг в канал с jitter и разовыми датами, режим «Объявления» с альбомами, мультиботы);
     - ПК / Windows BotControl.exe / Termux desktop-web (облегчённый JSON-формат: команды, триггеры по целым словам, клавиатура снизу, случайные наборы, текстовые анимации, до 3 URL-ссылок, расписание по числовому chat_id; БЕЗ ИИ, JS, фото-анимаций, send_dice и callback-кнопок).
   • Кто будет пользоваться ботом (один владелец, группа друзей, подписчики канала, клиенты)?
   • Нужен один бот или несколько разделённых ботов (например, один для уведомлений, другой для ИИ/развлечений)?

2. ИММЕРСИВНОСТЬ, СТИЛЬ И ЛИЧНОСТЬ БОТА
   • Насколько иммерсивным должен быть бот?
     - Уровень 1 (Утилитарный): быстрые, сухие, точные ответы без лишних пауз и декора;
     - Уровень 2 (Дружелюбный / живой): тёплый тон, эмодзи, короткая задержка «печатает…», подсказки во всплывающих уведомлениях кнопок, лёгкие индикаторы прогресса;
     - Уровень 3 (Максимально иммерсивный / игровой / ролевой): роль-персонаж, реалистичная пауза «печатает…», многокадровые ASCII-анимации или фото-флипбуки / квесты с картинками, правка сообщений на лету без спама новыми сообщениями, игровые броски (🎲🎯🎰), случайные саркастичные/атмосферные реплики и уточняющие вопросы.
   • Язык общения, обращение («ты»/«вы»), подстановка имени пользователя ({user}), текста ({text}) или ника бота ({bot}).
   • Запреты в стиле и содержании (без канцелярита, без мата, ограничения по длине и т.д.).

3. НУЖЕН ЛИ ЛОКАЛЬНЫЙ ИИ (ТОЛЬКО ДЛЯ ANDROID)
   • Помни главное правило BotControl: всё предсказуемое (команды, меню, кнопки, наборы, анимации, расписание) реализуется КОДОМ и работает мгновенно без ИИ. Локальная LLM на телефоне — отдельная опция, которая срабатывает ТОЛЬКО по команде /chat (или /ai) и по правилам с действием «ИИ».
   • Если ИИ нужен:
     - На какие именно сообщения/команды должен отвечать ИИ (/chat <вопрос>, правило по ключевому слову, кнопка клавиатуры)?
     - Какой характер (SYSTEM_PROMPT): роль, манера речи, длина ответа, правила и запреты?
     - Какую модель/движок планирует пользователь:
       * MediaPipe (.task / .bin, напр. Gemma-3 1B) — настраиваются temperature (0.1–1.5), Top-K (1–64) и max_tokens (64–1024);
       * LiteRT-LM (.litertlm, напр. Qwen3 0.6B, Gemma-3n E2B) — работает только max_tokens (температуру и Top-K задаёт сам движок).
     - Нужна ли память диалога (MAX_HISTORY: 0, 2, 4, 6, 8 или 10 последних реплик)?
   • Если ИИ НЕ нужен — явно уточни, что ИИ отключаем и всю логику строим на правилах, наборах и JS-скриптах.

4. ПОВЕДЕНИЕ, ПАУЗЫ И РЕАКЦИЯ НА НЕИЗВЕСТНЫЕ СООБЩЕНИЯ
   • Имитация набора текста «печатает…» (DEFAULT_TYPING_SECONDS): 0 (выкл), 1, 2, 3, 4 или 5 сек?
   • Антифлуд / кулдаун на неизвестные сообщения (ANSWER_COOLDOWN): 0 (нет), 5, 10, 15, 30 или 60 сек?
   • Что делать, если пользователь написал сообщение, не подходящее ни под одну команду/кнопку/фразу (и не /chat):
     - Вариант А: молчать (пустой запасной ответ, уточняющие вопросы выключены);
     - Вариант Б: отвечать случайной фразой из CLARIFY_QUESTIONS (какие фразы добавить?);
     - Вариант В: присылать единый фиксированный запасной ответ (текст подсказки/меню).

5. КОМАНДЫ И ГЛАВНОЕ МЕНЮ TELEGRAM
   • Какие команды нужны (обязательны /start и /help; допустимы только a-z, 0-9, _ до 32 символов, до 20 команд на пару scope/язык в кнопке «Меню» Telegram)?
   • Нужны ли отдельные списки команд для лички (BotCommandScopeAllPrivateChats), групп (BotCommandScopeAllGroupChats) или админов (BotCommandScopeAllChatAdministrators) и разные языки (language_code)?
   • Что запускает каждая команда: текст, случайный ответ из набора, анимацию, кубик, медиа (стикер/GIF/видео/файл/голосовое/аудио), опрос (send_poll), пошаговую анкету (FSM), JS-скрипт или ИИ?

6. ТРИГГЕРЫ НА СЛОВА И НИЖНЯЯ КЛАВИАТУРА ЧАТА
   • Нужна ли постоянная клавиатура внизу чата (ReplyKeyboardMarkup)? Какие кнопки, сколько колонок (1–4), нужна ли one_time_keyboard, подсказка ввода (input_field_placeholder), спецкнопки телефона (request_contact) и геопозиции (request_location), или скрытие клавиатуры (ReplyKeyboardRemove)?
   • Какое действие должно выполняться при нажатии каждой кнопки нижней клавиатуры?
   • Нужны ли реакции «Содержит фразу» (с опцией по целым словам wholeWord) или регулярные выражения regexp=r"..."?

7. INLINE-КНОПКИ ПОД СООБЩЕНИЯМИ (ДО 12 КНОПОК И 8 РЯДОВ НА ANDROID)
   • Под какими сообщениями (какие правила или события расписания) нужны inline-кнопки и в каком порядке рядов (markup.row(...))?
   • Для каждой кнопки уточни:
     - Надпись и нужна ли всплывашка-тост (toast, до 180 симв., держится ~3 с);
     - Нужна ли разметка parse_mode ("HTML" или "MarkdownV2")?
     - Что делает кнопка:
       1) Отвечает текстом (новым сообщением ИЛИ правит текущее сообщение под собой);
       2) Выбирает случайную фразу из набора (новым сообщением ИЛИ правит текущее);
       3) Переключается на вложенное подменю (submenu до 3 уровней с автоматической кнопкой «⬅️ Назад»);
       4) Запускает локальный ИИ по промту кнопки (llm / ask_llm);
       5) Отправляет медиа (photo/sticker/animation/document/video/voice/audio по file_id или URL);
       6) Запускает анимацию (новым сообщением ИЛИ анимирует это же сообщение с сохранением кнопок — слайдер/квест);
       7) Бросает Telegram-кубик (🎲 🎯 🏀 ⚽ 🎳 🎰);
       8) Включает/выключает напоминания (reminders_on = True/False + тост повторного нажатия «Уже работает»);
       9) Клиентские кнопки: ссылка URL, Telegram Mini App (web_app), копирование текста (copy_text) или inline-запрос в чат (switch_inline);
      10) Запускает JS-скрипт handle(e) (с доступом к памяти db) или пошаговую анкету FSM (в UI кнопка «📋 Запустить анкету»).

8. НАБОРЫ СЛУЧАЙНЫХ ОТВЕТОВ (PACKS)
   • Какие тематические списки фраз нужны (шутки, советы, цитаты, предсказания, факты, сарказм, призы для слота)?
   • Сколько вариантов генерировать в каждом наборе (импорт до 500, экспорт до 300; для яркого живого бота лучше 15–50+ вариантов)?
   • Нужен ли режим «без повторов до конца списка» (shuffleBag в «Наборах ответов»)?

9. АНИМАЦИИ, ФОТО-СЛАЙДЫ, МЕДИА И ИГРОВЫЕ ЭЛЕМЕНТЫ
   • Нужны ли анимации через редактирование одного сообщения?
     - Готовые эффекты: spinner, progress, dots, countdown (с какого числа 1–30), typewriter, matrix, slot (можно с итогом из набора pack=...), moon, clock, heart;
     - Свои текстовые кадры / ASCII-арт (2–60 кадров, моноширинный mono=True, разделитель ---);
     - Фото-флипбуки / слайдеры / визуальные квесты (кадры формата "photo: https://...\nподпись"; если есть ссылки на картинки — попроси URL или предложи режим для вставки фото из галереи телефона уже в приложении);
     - Темп кадров (delay от 0.5 до 3.0 сек — Telegram ограничивает правки до ~1 в секунду; при 429 приложение само выдерживает retry_after) и количество повторов (loops 1–5 в UI, 1–10 в коде).
   • Нужны ли анимированные эмодзи send_dice (🎲 🎯 🏀 ⚽ 🎳 🎰), опросы (send_poll) или готовые медиа по file_id / URL (стикеры send_sticker, GIF send_animation, голосовые send_voice, документы send_document, видео/аудио)?

10. СКРИПТОВАЯ ЛОГИКА И ПАМЯТЬ (JS В ПЕСОЧНИЦЕ RHINO, ANDROID)
    • Нужны ли вычисления или мини-логика на JavaScript: калькулятор, счётчик, баланс/очки, конвертер, генератор чисел/паролей, таймер/дата, разбор параметров команды (e.args), проверка условий?
    • В JS-песочнице `function handle(e) { ... return "..."; }` доступны поля: `e.user`, `e.text`, `e.chatId`, `e.username`, `e.userId`, `e.chatType`, `e.args`, `e.messageId`, `e.replyToText`, `e.kind`, `e.fileId`.
    • Начиная с `v1.9.0` в скриптах доступна персистентная память `db` в Room SQLite: `db.get(k, def?)`, `db.set(k, v)`, `db.del(k)`, `db.incr(k, d?)`, `db.keys()` (на пользователя) и `db.getGlobal/setGlobal/delGlobal/incrGlobal/globalKeys` (общие для бота). Запрещены только сети, файлы и `java.*`.

11. РАСПИСАНИЕ НАПОМИНАНИЙ И АВТОПОСТЫ В КАНАЛ
    • Нужны ли автоматические сообщения по расписанию?
    • Точное время (ЧЧ:ММ), дни недели (каждый день, Пн–Пт будни, Пн–Чт, только Пт, Сб–Вс выходные, отдельные дни) ИЛИ разовая отложенная дата `YYYY-MM-DD` (`onceDate` в UI «Напоминания»), текст и ротация вариантов через `" | "` по дням года.
    • Нужен ли плавающий сдвиг времени `jitterMin` (`±5 / ±10 / ±15 / ±30` минут в UI «Напоминания»), форматирование `HTML`/`MarkdownV2` или ID темы форума `threadId`?
    • Нужны ли inline-кнопки под конкретным напоминанием?
    • Куда отправлять: в личный чат с пользователем (`lastChatId`) или в канал (`»канал`)?

12. БАЗА ПОДПИСЧИКОВ, РОЛИ, ПОДПИСКА НА КАНАЛ, АНКЕТЫ (FSM), РАССЫЛКИ И ОБЪЯВЛЕНИЯ (ANDROID v1.9.0)
    • Нужна ли пошаговая анкета/заявка/квиз без кода (`FsmScreen`: шаги text/number/phone/photo/location/button, ветвления, `/back`, `/cancel`, отправка сводки админам или в канал, подстановка `{переменных}`)?
    • Нужны ли роли пользователей (`user` / `vip` / `admin`), список `adminIds`, ограничение отдельных команд только для админов/VIP, или обязательная проверка подписки на канал перед использованием бота (`getChatMember`)?
    • Планируются ли массовые рассылки по базе подписчиков или отдельным сегментам (роль / тег)?
    • Есть ли канал публикаций (`@channel` или `-100...`) и нужен ли встроенный режим «Объявления» (`LISTINGS_ON = True`: альбомы фото `sendMediaGroup`, лимит активных объявлений на пользователя, редактирование фото и уведомления админу)?

13. АВТОПРОВЕРКА ПОСЛЕ ИМПОРТА

Когда пользователь ответил на вопросы:
1. Если выбрана платформа ANDROID — выведи:
   а) РОВНО ОДИН блок валидного Python-кода конфигурации BotControl, строго соблюдая ВСЕ технические правила грамматики ScriptImporter:
      - НИКАКИХ `import`, НИКАКИХ f-строк с выражениями, НИКАКИХ вложенных словарей и `random.randint` в `get_today_schedule`. Для форматирования в `send_message(...)` обязательно указывай `parse_mode="HTML"` или `parse_mode="MarkdownV2"` (без него теги не рендерятся); стикеры/GIF/документы/опросы передаются штатно через `bot.send_sticker`, `bot.send_animation`, `bot.send_document`, `bot.send_poll`; регулярки — через `@bot.message_handler(regexp=r"...")`.
      - Порядок блоков (один самодостаточный файл = все настройки + наборы + кадры + хелпер + правила): заголовок-комментарий → `BOT_TOKEN = "НЕ_ИМПОРТИРУЕТСЯ"` → (если нужен ИИ) `SYSTEM_PROMPT = ( "..." "..." )`, `LLM_MAX_TOKENS`, `LLM_MAX_TOP_K`, `payload = { "temperature": ... }`, `MAX_HISTORY` → `ANSWER_COOLDOWN`, `DEFAULT_TYPING_SECONDS` → `CHANNEL_ID` / `LISTINGS_ON` (если нужны) → наборы `ИМЯ_НАБОРА = [ ... ]`, кадры `ANIM_* = [ ... ]` и `CLARIFY_QUESTIONS = [ ... ]` → хелпер `def play_animation(...)` (если есть анимации) → `def chat_keyboard():` (если нужна нижняя клавиатура) → обработчики `@bot.message_handler(...)` (команды `/start` и `/help` обязательны!) → `@bot.callback_query_handler(func=lambda call: True)` + функции inline-меню `def ..._keyboard():` → `def get_today_schedule(now):` (если есть расписание) → `bot.set_my_commands([...])` (если задаётся описание меню).
      - В списках КАЖДЫЙ элемент — на отдельной строке; закрывающая `]` — НА ОТДЕЛЬНОЙ СТРОКЕ! Комментарий `# Название набора` сразу в строке `ИМЯ = [  # Название` задаёт красивое русское имя набора. Каждый `NAME` в `random.choice(NAME)` или `pack=NAME` обязательно объявляй списком в ЭТОМ ЖЕ файле (чтобы конфиг работал на чистом боте и в v1.7.4; в v1.7.5+ при доимпорте фрагмента набор также умеет подхватываться из библиотеки бота).
      - Если бот использует анимации, ОБЯЗАТЕЛЬНО включи эталонный хелпер `def play_animation(chat_id, frames, delay=0.7, final=None, reply_markup=None, message_id=None, loops=1, pack=None, mono=False, text="", **kw):` с циклом `for frame in frames:` и `bot.edit_message_text(...)` (см. раздел 2.10). В `v1.7.5+` имя `play_animation` распознаётся и нативно без `def`, но явный `def play_animation(...)` гарантирует 100% работу также в `v1.7.4` и валидность Python-файла. Не выдумывай собственные необъявленные функции-помощники для отправки ответов/анимаций.
      - Соблюдай жёсткие лимиты, чтобы ничего не обрезалось: `CLARIFY_QUESTIONS <= 50`, наборы при импорте `<= 500` (при экспорте `<= 300`), нижняя клавиатура `<= 12` кнопок по `<= 32` симв., inline-меню `<= 12` кнопок / `<= 8` рядов (надпись `<= 64`, `toast <= 180`), текст ответа правила/кнопки `<= 4000`, подпись `photo:` `<= 1024` (обычное фото `<= 1000`), `SYSTEM_PROMPT <= 16000`, меню `set_my_commands <= 20`, анимация `delay` `0.5..3.0` с и кадров `<= 60`.
      - Встроенные JS-скрипты (если нужны) передавай в виде `run_script("function handle(e) { ... }")` с экранированными кавычками и `\n` — либо укажи, в какое правило их вставить через встроенный JS-редактор.
      - НЕ занимай зарезервированные имена (`BOT_TOKEN`, `SYSTEM_PROMPT`, `LLM_MAX_TOKENS`, `LLM_MAX_TOP_K`, `MAX_HISTORY`, `ANSWER_COOLDOWN`, `DEFAULT_TYPING_SECONDS`, `LISTINGS_MODE`, `LISTINGS_ON`, `LISTINGS`, `CHANNEL_ID`, `CHANNEL`, `CHANNEL_USERNAME`, `CHANNEL_NAME`, `CLARIFY_QUESTIONS`, `CLARIFY`, `schedule`, `commands`, `content_types`, `messages`, `history`, `days`, `buttons`, `menu`, `items`, `payload`, `choices`, `keyboards`, `allowed_updates`, `admins`, `admin_ids`, `users`, `get_today_schedule`, `cmd_*`) для своих наборов и функций!
      - Каждый объявленный `InlineKeyboardMarkup` обязательно прикрепи через `reply_markup=имя_меню()` в команде/правиле или 4-м элементом кортежа расписания `(H, M, "текст", имя_меню())`, иначе он не попадёт в бот!
      - У каждой кнопки нижней клавиатуры `chat_keyboard()` (кроме кнопок встроенного режима «Объявления») обязательно должен быть обработчик `@bot.message_handler(func=lambda m: m.text == "...")`.
      - Клавиатуру `chat_keyboard()` обязательно прикрепи к `/start` через `reply_markup=chat_keyboard()` (если к `/start` уже крепится inline-меню, опиши `chat_keyboard()` единственной `ReplyKeyboardMarkup`-функцией в файле — импортёр подхватит её автоматически).
   б) После блока кода — КОРОТКИЙ чеклист донастройки и проверки в интерфейсе BotControl:
      - при замене старого конфига на новый — сначала выполнить **«♻ Сброс настроек бота»**;
      - после «🔍 Разобрать» убедиться, что число правил совпадает с количеством команд/кнопок/фраз, замечаний `0`, пропущенных правил `0` и кнопок «без действия» `0`;
      - что включается в UI: если нужен ИИ — переключатель «ИИ» в карточке бота и модель `.task`/`.litertlm`; если нужно молчать на незнакомые сообщения — выключить «Уточняющие вопросы» и очистить «Запасной ответ»; для JS — тест кнопкой «▶ Выполнить»; для фото с телефона — «🎞 Анимация → 🖼 Фото из галереи»; контрольный прогон тестовых фраз в «🧪 Имитация».

2. Если выбрана платформа DESKTOP-WEB / WINDOWS (`BotControl.exe`):
   а) Выведи РОВНО ОДИН валидный JSON-объект формата `{"format":"botcontrol","version":1,"name":"...","scenarios":[...],"buttons":[...],"schedule":[]}` без лишних полей (без Python, без JS, без callback-кнопок и ИИ).
   б) Приведи пошаговую инструкцию импорта и тестирования в веб-интерфейсе.

### 2.1. Как работает логика бота (`BotBrain` и `LocalBotService`)

Когда пользователь пишет сообщение боту в Telegram (или в экран **«🧪 Имитация»** в приложении), решение принимается строго в таком порядке:

0. **Учёт подписчика, бан и проверка подписки на канал (`v1.9.0`):**
   - `BotUserEntity` автоматически фиксирует/обновляет пользователя в Room (`chatId`, `userId`, `username`, `firstName`, `lastSeenAt`, `msgCount`).
   - Если `isBanned = true` (и пользователь не входит в `adminIds` / `role == "admin"`) — сообщения и нажатия кнопок игнорируются.
   - Если в «Настройках бота» задан обязательный канал (`requiredChannel`) — для не-админов проверяется статус через `getChatMember` (кеш 60 с; можно обойти для отдельных правил флагом `skipSubCheck`). При отсутствии подписки выдаётся экран блокировки с кнопками «📢 Подписаться» и «✅ Проверить подписку».
1. **Режим «Объявления» (`ListingEngine`, если `listingsOn = true`):**
   - Перехватывает глобальные триггеры (`📝 Разместить объявление` / `/new`, `📋 Мои объявления` / `/my`, `❌ Отмена` / `/cancel`), `/start` (сохраняя собственное приветствие правила `/start`) и активные шаги визарда (описание → выбор контакта → телефон → фото до 3 шт → предпросмотр → публикация в канал, 2+ фото альбомом `sendMediaGroup`).
   - Если задан лимит `listingMaxPerUser`, не даёт одному пользователю создать больше разрешённого числа активных объявлений; при удалении объявления уведомляет админов.
2. **Пошаговые анкеты без кода (`FsmEngine`, `v1.9.0`):**
   - Проверяет активный шаг анкеты пользователя (`botId:chatId`) или триггер запуска новой анкеты.
   - Поддерживает `/back` (`⬅️ Назад`), `/cancel` (`❌ Отмена`), валидацию типов (`text`, `number`, `phone`, `photo`, `location`, `button`, `any`), ветвление, сохранение ответов в `BotUserEntity.varsJson` и отправку сводки админам/в канал.
3. **Декларативные правила (`bot_rules` в базе Room, в порядке `id` сверху вниз):**
   - Проверяются только включённые (`enabled = true`) правила данного бота (`botId`).
   - Типы правил:
     - `command`: совпадение первого слова сообщения (до `@botname`, без учёта регистра) с `/командой`.
     - `button`: точное совпадение всего текста сообщения с надписью кнопки (без учёта регистра).
     - `regex`: сопоставление регулярного выражения без учёта регистра.
     - `contains`: вхождение непустого `pattern` в текст сообщения (с опцией `wholeWord` для целых слов `\p{L}\p{N}_`).
   - Перед выполнением проверяются права доступа (`RuleOptions.adminOnly`, `requiredRole`). Первое подошедшее разрешённое правило выполняется (`text`, `pack`, `anim`, `dice`, `media`, `poll`, `script` или `llm`) с подстановкой `{переменных}` пользователя.
4. **Нажата кнопка нижней клавиатуры без правила:**
   - Если текст совпадает с кнопкой из `store.keyboard(botId)`, но правила под неё нет — бот подсказывает владельцу, как добавить правило для этой кнопки.
5. **Явный ИИ-сценарий (`/chat <вопрос>` или `/ai <вопрос>`):**
   - ИИ отвечает только здесь, по правилам с действием `llm` и по inline-кнопкам `action = "llm"`.
6. **Антифлуд (`cooldownSec`):**
   - Срабатывает **только на незнакомых сообщениях**, дошедших до шага 6 (`botId:chatId`).
7. **Запасной ответ (`fallback`):**
   - Если `clarifyEnabled = true` и список `clarifyQuestions` не пуст → случайный вопрос из `clarifyQuestions`. Иначе → `defaultReply` (если пустой — бот молчит).

**Имитация набора текста (`typingSeconds`):**
- Для обычных ответов (`text`, `pack`, `script`, `fallback`) и напоминаний в чат перед отправкой вызывается `sendChatAction("typing")` и выдерживается пауза `typingSeconds` (0–5 с).
- Для ответов ИИ (`llm`) `sendChatAction("typing")` вызывается в момент старта генерации моделью, дополнительная задержка после ответа не добавляется.
- Для анимаций (`anim`) и кубиков (`dice`) первый кадр/эмодзи отправляется сразу без лишней задержки.

### 2.2. Все типы действий для правил и кнопок

| Действие | В правилах (`BotRuleEntity`) | В inline-кнопке (`InlineBtn`) | Что делает |
|---|---|---|---|
| **Текст** (`text`) | Да | Да (+ опция `edit = true`) | Отправляет текст (или правит сообщение под inline-кнопкой). Поддерживает `parse_mode` (`HTML`/`MarkdownV2`), флаги доставки и плейсхолдеры `{user}`, `{username}`, `{user_id}`, `{chat_id}`, `{args}`, `{arg1..3}`, `{bot}`, `{date}`, `{time}`. |
| **Набор** (`pack`) | Да | Да (+ опция `edit = true`) | Выбирает фразу из набора `ReplyPack` (обычный случайный или `shuffleBag` — без повторов до конца списка). |
| **Анимация** (`anim`) | Да | Да (+ опция `edit = message_id`) | Отправляет первый кадр и правит сообщение кадр за кадром (`editMessageText` или `editMessageMedia`/`editMessageCaption`). |
| **Кубик** (`dice`) | Да | Да | Отправляет анимированный эмодзи `sendDice`: `🎲`, `🎯`, `🏀`, `⚽`, `🎳`, `🎰` (результат вычисляет Telegram). |
| **Медиа** (`media`) | Да | Да | Отправляет `photo`, `sticker`, `animation`, `document`, `video`, `voice` или `audio` по `file_id`, URL или локальному пути. |
| **Опрос** (`poll`) | Да | Нет | Отправляет опрос `sendPoll` (2–10 вариантов, анонимность, множественный выбор). |
| **Скрипт JS** (`script`) | Да | Да (+ опция `edit = true`) | Выполняет `function handle(e)` в песочнице Rhino (`e.user`, `e.text`, `e.chatId`, `e.username`, `e.userId`, `e.chatType`, `e.args`, `e.messageId`, `e.replyToText`, `e.kind`, `e.fileId`) + персистентная память `db` в Room (`v1.9.0`). |
| **ИИ на устройстве** (`llm`) | Да | Да (+ опция `edit = true`) | Генерирует ответ локальной моделью (`DeviceLlm`) с учётом `SYSTEM_PROMPT`, истории `ChatMemory` и параметров бота. |
| **Запуск анкеты FSM** (`fsm`) | Через `FsmEngine` | Да (`v1.9.0`) | Запускает пошаговую анкету (`FsmFlow`) по её названию/ID/команде запуска. |
| **Подменю / Назад** (`submenu`, `back`) | Нет | Да | Переключает сообщение во вложенное меню (до 3 уровней) со стеком возврата «⬅️ Назад» без отправки лишних сообщений. |
| **Клиентские кнопки** (`url`, `web_app`, `copy_text`, `switch_inline`) | Нет | Да | Открытие ссылки (`url`), Telegram Mini App (`web_app`), копирование текста (`copy_text`) или вставка inline-запроса в чат (`switch_inline`). |
| **Вкл/выкл напоминаний** (`reminders_on`, `reminders_off`) | Нет (делается через кнопку) | Да (всегда `edit = true`) | Меняет `remindersOn(botId)`, правит текст под кнопкой с сохранением меню; при повторном нажатии показывает `toastNoChange`. |

> **Подстановки и форматирование (`v1.8.0`):**
> - В коде Python `{name}`, `{first_name}`, `{user_name}`, `{msg.from_user.first_name}` автоматически нормализуются в `{user}`; доступны также `{username}`, `{user_id}`, `{chat_id}`, `{args}`, `{arg1}`, `{arg2}`, `{arg3}`, `{bot}`, `{date}`, `{time}`.
> - `parse_mode`: по умолчанию обычный текст, либо выберите `HTML` / `MarkdownV2` в «Опции отправки» (при ошибке разметки Telegram API HTTP 400 бот автоматически откатится к обычному тексту).

### 2.3. Клавиатура чата vs Inline-кнопки: правила проектирования

#### Нижняя клавиатура чата (`ReplyKeyboardMarkup`)
- Постоянные кнопки под полем ввода пользователя.
- В UI («Сценарии → Кнопки бота») кнопки клавиатуры и их действие (`text` / `pack`, а существующие сложные действия сохраняются) редактируются в одном диалоге.
- В коде задаётся функцией `chat_keyboard()`:
  ```python
  def chat_keyboard():
      markup = ReplyKeyboardMarkup(resize_keyboard=True)
      markup.row(KeyboardButton("🎲 Шутка"), KeyboardButton("⏳ Отсчёт"))
      return markup
  ```
- Ограничения:
  - Надпись обрезается до **32 символов**.
  - При нажатии кнопки пользователь фактически отправляет её текст в чат → для каждой кнопки должно существовать правило `m.text == "Надпись"` (исключение — триггеры встроенного режима «Объявления»).
  - В Telegram клавиатура отображается с момента отправки сообщения с `reply_markup=chat_keyboard()` (обычно в `/start`).

#### Inline-кнопки под сообщением (`InlineKeyboardMarkup`)
- Крепятся под ответом конкретного правила или под событием расписания.
- **Лимиты:** до **12 кнопок** на одно сообщение (`MAX_MENU_BUTTONS = 12`), раскладка до **8 рядов** (`markup.row(...)`). Если `row = 0`, раскладываются по 2 в ряд.
- **Параметры кнопки:**
  - `label` — текст на кнопке;
  - `toast` — всплывающее уведомление сверху экрана (до 180 симв., держится ~3 с);
  - `toastNoChange` — отдельная всплывашка для переключателей `reminders_on`/`reminders_off`, если состояние уже включено/выключено (в коде распознаётся как `answer_callback_query` сразу перед `return` до присваивания флага);
  - `edit` — править исходное сообщение (`editMessageText` / `editMessageMedia`), сохраняя его меню, вместо отправки нового сообщения.
- **Важно про импортёр:**
  - Если у кнопки `callback_data="start"` или `"stop"` (а также `"run"`, `"on"`, `"off"`, `"pause"`, `"resume"`, `"go"`, `"reminders_on"`, `"reminders_off"`) не найден обработчик, импортёр автоматически назначит штатное включение/выключение напоминаний.
  - Для всех остальных `callback_data` обязательно нужна явная ветка в `@bot.callback_query_handler`.
  - Если в обработчике кнопки подставить другое `reply_markup=sub_menu()`, начиная с `v1.8.0` импортёр автоматически создаёт **вложенное подменю** (`action = "submenu"`, глубина до 3 уровней) со стеком возврата и кнопкой «⬅️ Назад» — причём `ScriptImporter` также распознаёт кнопки `web_app`, `copy_text`, `switch_inline` и вызовы `ask_llm(...)`!

### 2.4. Все 11 режимов анимаций (`Anim.kt`) и фото-слайдеры

Анимации работают путём отправки первого сообщения (или правки того сообщения, на котором нажата inline-кнопка) и последовательного редактирования кадров.

**Общие лимиты:**
- Шаг `delay`: строго от `0.5` до `3.0` секунд (`MIN_INTERVAL = 500`, `MAX_INTERVAL = 3000` мс) — Telegram ограничивает частые правки и при превышении возвращает HTTP 429 (`AnimPlayer` при 429 ждёт `retry_after`, повторяет кадр и пишет номер кадра / пропущенный `not modified` кадр в журнал).
- Потолок кадров: **60** (`MAX_FRAMES = 60`; в `v1.7.5+` при превышении `frames * loops > 60` или выходе `delay`/`loops` за диапазон импортёр предупреждает в «Замечаниях»).
- Повторы `loops`: `1–5` в UI-редакторе, `1–10` в движке.
- Итоговый текст `final` (или случайный выбор из набора `pack=...`): появляется последним шагом уже обычным шрифтом (не `<pre>`) и вместе с `reply_markup`.
- Поддерживается `{user}`.

#### Таблица готовых эффектов (`PRESETS`)

| `preset` | Название | Шаг по ум. | Цикличный? | Моно (`<pre>`)? | Особенности |
|---|---|---|---|---|---|
| `"spinner"` | ⠋ Спиннер | `0.6 с` | Да | Нет | Крутящийся Брайль-индикатор `⠋..⠏` + `text`. |
| `"progress"` | ▰ Прогресс-бар | `0.6 с` | Нет | Нет | 11 кадров: `▱→▰` от `0%` до `100%` + `text`. |
| `"dots"` | … Точки | `0.6 с` | Да | Нет | `text`, `text.`, `text..`, `text...`. |
| `"countdown"` | ⏳ Отсчёт | `1.0 с` | Нет | Нет | `⏳ N … ⏳ 1` (`count` `1–30`, в UI `1–10`), итог по умолчанию `🚀`. |
| `"typewriter"` | ⌨️ Печатная машинка | `0.5 с` | Нет | Нет | Постепенное появление `text` (или `final`) с курсором `▌` (до ~20 шагов). |
| `"matrix"` | 🟩 Матрица | `0.6 с` | Да | **Да** | Цифровой дождь `01ｱｲ…` (`6 * loops` кадров) + опциональная подпись `text`. |
| `"slot"` | 🎰 Слот-машина | `0.5 с` | Нет | Нет | 8 кадров вращения `🎰 \| 🍒 💎 7️⃣ \|`; идеально сочетается с `pack=НАБОР` в финале! |
| `"moon"` | 🌕 Фазы луны | `0.6 с` | Да | Нет | `🌑🌒🌓🌔🌕🌖🌗🌘` + `text`. |
| `"clock"` | 🕐 Часы | `0.6 с` | Да | Нет | `🕐..🕛` + `text`. |
| `"heart"` | ❤️ Сердце | `0.6 с` | Да | Нет | `❤️🧡💛💚💙💜` + `text`. |
| `"custom"` | 🎞 Свои кадры | `0.8 с` | Да | По выбору | Любые текстовые/ASCII-кадры (разделитель `---` в UI) или фото-кадры `photo:`. |

#### Кастомная ASCII-анимация (текстовый флипбук)
- Передавайте `mono=True` — каждый кадр оборачивается в HTML `<pre>` с экранированием `& < >`.
- Если кадр начинается с пробела или пустой строки `\n`, приложение автоматически добавляет невидимый символ `\u2800`, чтобы Telegram не схлопнул отступы.

#### Фото-анимации и кнопочные слайдеры (`photo:`)
- Любой кадр в `custom`-списке может начинаться со строки `photo: <ссылка_https | file_id | путь_на_телефоне>`, а со второй строки нести подпись (до 1024 символов):
  ```python
  ANIM_QUEST = [
      "photo: https://example.com/forest.jpg\nГлава 1. Тёмный лес...",
      "Ты слышишь странный шорох в кустах.",
      "photo: https://example.com/hut.jpg\nГлава 2. Огонёк в хижине.",
  ]
  ```
- Как работает движок:
  - Первый кадр отправляется через `sendPhoto` (или сразу редактирует уже существующее фото-сообщение по `message_id=call.message.message_id`).
  - Кадр с **другой** картинкой вызывает `editMessageMedia`.
  - Последующий кадр **без** `photo:` оставляет предыдущую картинку и меняет только подпись (`editMessageCaption`) — это выглядит плавно и экономит запросы.
  - При `message_id=call.message.message_id, reply_markup=main_menu()` меню остаётся под фото — так делаются **интерактивные презентации, каталоги товаров и визуальные квесты**! *(Важно: правка картинки «на месте» работает, когда исходное сообщение тоже отправлено с фото — например, `/start` запускает обложку через `play_animation` с `photo:`; если исходное сообщение было текстовым, приложение автоматически отправит слайд новым сообщением, без ошибки.)*
  - В самом Android-редакторе (`AnimEditor`) пользователь может также добавлять картинки прямо из галереи телефона (`🖼 Фото из галереи`).

### 2.5. JS-скрипты в песочнице и персистентная память `db` (`BotScript`)

- Движок: **Mozilla Rhino** в режиме чистого интерпретатора (`optimizationLevel = -1`, `ClassShutter { false }`).
- **Контракт функции:**
  ```javascript
  function handle(e) {
    // Поля события e:
    //   e.user, e.text, e.chatId, e.username, e.userId,
    //   e.chatType, e.args, e.messageId, e.replyToText, e.kind, e.fileId
    //
    // Персистентная память db (Room SQLite, v1.9.0):
    //   По пользователю: db.get(k, def?), db.set(k, v), db.del(k), db.incr(k, d?), db.keys()
    //   Общая на бота:   db.getGlobal(k, def?), db.setGlobal(k, v), db.delGlobal(k), db.incrGlobal(k, d?), db.globalKeys()
    var visits = db.incr("visits", 1);
    return "Привет, " + e.user + "! Заходов: " + visits;
  }
  ```
- **Доступно:** стандартные объекты JavaScript (`Math`, `Date`, `JSON`, `String`, `Array`, `RegExp`, `parseInt`, `parseFloat`) и встроенный объект `db`.
- **Запрещено:** любые обращения к `java.*`, сети (`fetch`, `http`), файлам, `setTimeout`, потокам.
- **Где используется:**
  - В правилах (`actionType = "script"`) — редактируется в экране **«✎ код»** и сразу проверяется кнопкой **«▶ Выполнить»** (с отображением изменений `db`).
  - В inline-кнопках (`action = "script"`).
  - В Python-конфиге распознаётся через `run_script("function handle(e) { ... }")`.

### 2.6. Локальный ИИ на устройстве и параметры поведения

| Параметр в коде (Python) | Раздел в UI | Допустимые значения в UI | Назначение |
|---|---|---|---|
| `SYSTEM_PROMPT = ( "..." "..." )` | ИИ → Характер | Любой текст | Системный промт для ИИ (роль, стиль, правила). Переносы строк — `\n`. |
| `LLM_MAX_TOKENS` | Настройки ИИ | `64, 80, 128, 256, 512, 1024` | Максимальная длина ответа модели в токенах. |
| `LLM_MAX_TOP_K` | Настройки ИИ | `1, 5, 10, 20, 30, 40, 50, 64` | Top-K сэмплинг (только для MediaPipe `.task`/`.bin`). |
| `payload = { "temperature": ... }` | Настройки ИИ | `0.1 .. 1.5` (шаг `0.1`, также `1.2`, `1.5`) | Креативность ответа (только для MediaPipe `.task`/`.bin`). |
| `MAX_HISTORY` / `HISTORY_LIMIT` | Поведение и паузы | `0, 2, 4, 6, 8, 10` | Сколько последних реплик диалога помнит ИИ в `ChatMemory` (`botId:chatId`). |
| `DEFAULT_TYPING_SECONDS` | Поведение и паузы | `0, 1, 2, 3, 4, 5` | Сколько секунд показывать статус `печатает…` перед ответом. |
| `ANSWER_COOLDOWN` | Поведение и паузы | `0, 5, 10, 15, 30, 60` | Пауза между ответами на незнакомые сообщения (антифлуд). |
| `CLARIFY_QUESTIONS = [ ... ]` | Поведение и паузы | До 50 фраз | Случайные вопросы при срабатывании fallback (если включён тумблер уточняющих). |

**Особенности движков ИИ на устройстве:**
- Поддерживаются форматы **MediaPipe** (`.task`, `.bin`, например Gemma-3 1B IT) и **LiteRT-LM** (`.litertlm`, например Qwen3 0.6B, Gemma-3n E2B). Модели с пометками `web`, `qualcomm`, `qcs` для обычных телефонов не подходят.
- При выборе `.litertlm` движок сам управляет `temperature` и `Top-K`, поэтому в UI эти два списка скрываются и учитывается только `LLM_MAX_TOKENS`.
- Встроенный экран **«💬 Чат с ИИ»** позволяет проверить модель до запуска бота и посмотреть **«Процесс раздумий»**.

### 2.7. Расписание, каналы и режим «Объявления»

#### Расписание (`get_today_schedule(now)`)
- Проверяется каждые 20 секунд; событие отправляется **один раз в день** при совпадении дня недели и времени.
- **Окно допуска (catch-up):** если телефон заснул/перезапускался, пропущенное событие досылается в течение **5 минут** в Android (`CATCH_UP_MINUTES = 5`) или **10 минут** в `desktop-web`; более старые события за этот день пропускаются. При ошибке сети или `HTTP 429` событие **не помечается отправленным** и повторяется в пределах окна.
- В Android напоминания идут в `lastChatId` (первый чат/пользователь, написавший боту), если только событие не помечено `toChannel = true`.
- **Кортеж события:**
  - `(ЧАС, МИН, "текст")` — обычное напоминание.
  - `(ЧАС, МИН, "текст", меню())` — напоминание с inline-кнопками под ним.
  - Префикс `»канал ` в тексте (`"»канал Доброе утро!"`) → публикация в канал `CHANNEL_ID`.
  - Разделитель `" | "` в тексте (`"Вариант А | Вариант Б | Вариант В"`) → ротация вариантов по дню года (`DAY_OF_YEAR`) **как для постов в канал, так и для личных напоминаний** (`v1.7.5+`; в версиях `≤ v1.7.4` ротация работала только в канале).
- **Условия дней недели, которые понимает `ScriptImporter`:**
  - Кортежи до `if` → каждый день (`1..7`).
  - `if wd < 5:` / `if 0 <= wd <= 4:` → будни (Пн–Пт).
  - `if wd == 4:` → только пятница; `else:` внутри будней → Пн–Чт.
  - `if wd >= 5:` / `if wd in (5, 6):` → выходные (Сб–Вс).
  - Поддерживаются также `now.isoweekday()` (`1..7`), `not in`, вложенные `if`/`elif`/`else`.
- **Новое в расписании и наборах (`v1.8.0`–`v1.9.0`):**
  - Поддерживается случайный сдвиг времени **jitter** (`ScheduleEvent.jitterMin`: ±0/5/10/15/30 мин в UI, детерминирован по дню), разметка `HTML`/`MarkdownV2`, `threadId` форумов и **разовая дата `onceDate`** (`YYYY-MM-DD`, после отправки выключается сама).
  - Для наборов (`ReplyPack`) доступен режим **ShuffleBag** («не повторять фразы до исчерпания списка»).
  - На уровне Telegram API нативно поддерживаются `sendSticker`, `sendAnimation`, `sendDocument`, `sendVideo`, `sendVoice`, `sendAudio`, `sendPoll`, `sendMediaGroup`, `getChatMemberStatus`, а также вложенные inline-подменю до 3 уровней.

#### Канал и встроенный режим «Объявления» (`ListingEngine`)
- Включается константами `CHANNEL_ID = "@my_channel"` (или `"-100..."`) и `LISTINGS_ON = True` (либо в **«Настройках бота → Канал публикаций и объявления»**).
- Бот должен быть добавлен **администратором** канала с правом публикации и удаления сообщений.
- Что даёт режим из коробки:
  - Кнопки/команды `📝 Разместить объявление` (`/new`, распознаются также формулировки «добавить объявление», «новое объявление», «хочу отдать…`), `📋 Мои объявления` (`/my`), `❌ Отмена` (`/cancel`).
  - **Лимит объявлений на пользователя** (`listingMaxPerUser` в Настройках бота) и публикация **2+ фото одним альбомом** (`sendMediaGroup` + контактная кнопка, настройка `listingUseAlbum`).
  - Пошаговый визард: описание (до 800 симв.) → контакт (`✉️ Написать в личку` или `📞 Указать телефон`) → фото (0–3 шт.) → предпросмотр и публикация в канал.
  - **«📋 Мои объявления»:** статистика по автору, кнопки для последних 8 объявлений — `✏️` (изменить описание), `🖼 Фото` (сменить фото), `🔄` (переопубликовать) и `🗑` (удалить из канала; админы из `adminIds` могут удалять любое объявление и получают уведомление об удалении).

### 2.7.1. База подписчиков, роли, подписка на канал, рассылки и анкеты FSM (`v1.9.0`)

Настраивается прямо в интерфейсе Android-приложения поверх любого (в т.ч. импортированного) бота:
- **Подписчики (`UsersScreen`, Room `BotUserEntity` per-`botId`):** автоучёт каждого пользователя, роли (`user` / `vip` / `admin`), теги, ручной бан, отметка `403` (бот заблокирован), ручное добавление по ID и просмотр переменных `{var}`.
- **Роли и обязательная подписка (`BotSettingsScreen` + `LocalBotScreen`):** список `adminIds`, обязательный канал (`requiredChannel`, ссылка, свой текст) с кнопкой «✅ Проверить подписку» (`getChatMember`), а у правил — флаги `adminOnly`, `requiredRole` и `skipSubCheck`.
- **Пошаговые анкеты FSM (`FsmScreen` + `FsmEngine`):** шаги с проверкой (`text`, `number`, `phone`, `photo`, `location`, `button`, `any`), `/back`, `/cancel`, ветвление (`branchMap` / `DONE`), сохранение в `{var}` и отправка итога админам и/или в канал.
- **Массовые рассылки (`BroadcastScreen` + `BroadcastEngine`):** по всем активным подписчикам, по роли или тегу, с подстановкой `{переменных}`, `parse_mode`, медиа, inline-меню, троттлингом ~22 сообщ./с, обработкой `429 retry_after` и авто-пометкой `403`.

### 2.8. Главное меню Telegram (`setMyCommands`) и строгие правила импорта

- `bot.set_my_commands([BotCommand("start", "Запустить бота"), BotCommand("help", "Справка")])` задаёт кнопку «Меню» слева от поля ввода (до **20 команд**, имена только `^[a-z0-9_]{1,32}$`).
- Если `set_my_commands` не вызван явно, импортёр соберёт меню из всех команд правил автоматически.
- В Android `v1.7.4+` `setMyCommands` вызывается при запуске бота **только если список команд изменился** относительно прошлой успешной синхронизации (экономия лимитов Telegram / защита от 429).
- В `v1.7.5+`:
  - `play_animation(...)` распознаётся **нативно**, даже если `def play_animation(...)` не объявлен в коде; если же вызван неизвестный helper без `def`, импортёр выводит явное предупреждение, а экран импорта сообщает обо всех пропущенных пустых правилах.
  - При импорте короткого фрагмента вида `random.choice(EXISTING_PACK)` без повторного объявления списка `EXISTING_PACK = [...]` импортёр ищет подходящий набор среди уже сохранённых наборов текущего бота и общих наборов библиотеки (с пометкой `ℹ️ Набор ... взят из библиотеки бота`).
  - **Жёсткие лимиты импорта и хранения** (при превышении в `v1.7.5+` показывается предупреждение `ℹ️` в разделе «Замечания»):
    - `SYSTEM_PROMPT`: до **16 000** символов; запасной ответ `defaultReply`: до **4 000** символов;
    - `CLARIFY_QUESTIONS`: до **50** вопросов;
    - `ReplyPack` (набор): до **500** фраз при импорте (экспорт сохраняет до **300**);
    - `chat_keyboard()`: до **12** кнопок, надпись кнопки до **32** символов;
    - `InlineKeyboardMarkup`: надпись кнопки до **64** символов, всплывашка `toast` до **180** символов (обрезается при отправке), UI-редактор меню ограничивает до **12** кнопок и **8** рядов;
    - текст ответа правила/кнопки: до **4 000** символов (обрезается в `TelegramApi.sendMessage`); подпись к `photo:` анимации — до **1 024** символов (обычное фото — до **1 000**); JS при экспорте — до **4 000** символов;
    - `set_my_commands`: до **20** команд;
    - анимации: `delay` в диапазоне `0.5..3.0` с, `loops` `1..10`, до **60** кадров.

#### Полный список зарезервированных имён (НЕ использовать для наборов и своих функций)
- Константы настроек: `BOT_TOKEN`, `SYSTEM_PROMPT`, `LLM_MAX_TOKENS`, `LLM_MAX_TOP_K`, `MAX_HISTORY`, `ANSWER_COOLDOWN`, `DEFAULT_TYPING_SECONDS`, `CHANNEL_ID`, `CHANNEL`, `CHANNEL_USERNAME`, `CHANNEL_NAME`, `LISTINGS_MODE`, `LISTINGS_ON`, `LISTINGS`, `CLARIFY_QUESTIONS`, `CLARIFY`.
- Служебные имена списков: `schedule`, `content_types`, `commands`, `messages`, `history`, `days`, `buttons`, `menu`, `items`, `payload`, `choices`, `keyboards`, `allowed_updates`, `admins`, `admin_ids`, `users`.
- Имена функций: `get_today_schedule`, `cmd_*`, `play_animation` (для помощника анимации), а также списки `ANIM_*` и `*_FRAMES` (считаются кадрами анимации, а не наборами ответов).

### 2.9. Облегчённый формат JSON для `desktop-web` / `BotControl.exe`

Если пользователь просит бота для ПК/Windows/Termux (`tg-bot-control/desktop-web/`), LLM **не должна** генерировать Python-конфиг — для `desktop-web` используется строгий JSON (валидатор `parseGenerated` и `compile_bot`):

```json

  "version": 1,
  "name": "Название бота",
  "scenarios": [
    {
      "id": "welcome",
      "name": "Приветствие",
      "text": "Здравствуйте! Выберите действие.",
      "trigger": { "type": "command", "value": "/start" },
      "links": [{ "label": "Сайт", "url": "https://example.com" }]
    },
    {
      "id": "jokes",
      "name": "Случайная шутка",
      "text": "",
      "replies": ["Шутка 1", "Шутка 2"]
    },
    {
      "id": "loading",
      "name": "Загрузка",
      "text": "",
      "animation": {
        "preset": "progress",
        "text": "Обработка",
        "interval": 700,
        "loops": 1,
        "count": 5,
        "final": "Готово!",
        "frames": ""
      }
    }
  ],
  "buttons": [
    { "id": "btn-jokes", "label": "🎲 Шутка", "scenarioId": "jokes" },
    { "id": "btn-load", "label": "⏳ Проверка", "scenarioId": "loading" }
  ],
  "schedule": []
}
```

**Жёсткие ограничения формата `desktop-web`:**
- Никаких лишних ключей; строго `format`, `version`, `name`, `scenarios`, `buttons`, `schedule`.
- В одном сценарии нельзя совмещать `replies` и `animation`.
- В `trigger` допустимы только `command` (`^/[a-zA-Z0-9_]{1,32}$`) и `contains` (до 200 симв., срабатывает по целым словам).
- `links` — максимум **3 ссылки** (`http`/`https`, без логина и пароля).
- `buttons` — до **100** кнопок с уникальными (без учёта регистра) `label`.
- Для `schedule` нужен точный числовой `chatId` пользователя (`-?[0-9]{1,20}` — узнать его можно встроенной командой `/chatid`); дни задаются `0..6` (`0` = понедельник, `6` = воскресенье!).
- **Не поддерживаются:** ИИ на устройстве, JS-скрипты, inline-кнопки с callback-действиями, фото-анимации (`photo:`), `send_dice`, режим «Объявления».

## 3. Что LLM должна проверять перед выдачей кода (Self-Check)

1. Нет ни одного `import`, `f"..."`, вычисляемого выражения в аргументах `send_message(...)`, вложенного словаря или `random.randint` в `get_today_schedule`. (Регулярки `regexp=r"..."` и `parse_mode="HTML"`/`"MarkdownV2"` с `v1.8.0` поддерживаются нативно.)
2. Если используются анимации — в коде есть эталонный `def play_animation(...)` с циклом `for frame in frames:` и `bot.edit_message_text(...)` (гарантирует работу и в `v1.7.4`, и в `v1.7.5+`, никаких выдуманных необъявленных helper-функций).
3. Все списки наборов, кадров (`ANIM_*`) и `CLARIFY_QUESTIONS`, упомянутые в `random.choice(NAME)` или `pack=NAME`, объявлены в этом же файле; каждая закрывающая `]` вынесена на отдельную строку.
4. Для обычного текста без `parse_mode="HTML"`/`"MarkdownV2"` нет тегов (`<b>`, `**`), чтобы Telegram не показал их сырыми символами.
5. Есть `/start` и `/help` (в `/start` показана роль бота, inline-меню или прикреплена нижняя клавиатура).
6. У каждой inline-кнопки без `url`/`web_app`/`copy_text`/`switch_inline_query_current_chat` есть уникальный `callback_data` и отдельная ветка `if/elif call.data == "..."` в `@bot.callback_query_handler`.
7. У каждой кнопки нижней клавиатуры (кроме `request_contact`/`request_location`) есть правило `@bot.message_handler(func=lambda m: m.text == "...")`.
8. Соблюдены все лимиты: `delay` `0.5..3.0` с, кадров ≤ `60` (`frames * loops <= 60`), `CLARIFY_QUESTIONS` ≤ `50`, наборы ≤ `500` (экспорт ≤ `300`), нижняя клавиатура ≤ `12` кнопок × `32` симв., inline-кнопки ≤ `12` (рядов ≤ `8`, вложенность меню ≤ `3`, надпись ≤ `64`, `toast` ≤ `180`), текст ответа ≤ `4000`, меню команд ≤ `20` на пару `scope/language_code`.
